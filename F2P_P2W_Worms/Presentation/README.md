# Presentation

Слой связывает готовые данные Terrain с простым WPF-окном.
Генерация карты остаётся в Terrain. Представление использует R3 для уведомления
о новом результате и стандартные WPF-команды рисования для отображения.

## Файлы

| Файл | Назначение |
| --- | --- |
| `ViewModels/TerrainViewModel.cs` | Читает JSON, запускает генератор в фоне и публикует модель через R3 |
| `Views/TerrainView.xaml` | Содержит единственный `TerrainDebugSurface` с привязкой `Terrain.Value` |
| `Views/TerrainView.xaml.cs` | Инициализирует XAML-представление |
| `Views/TerrainDebugSurface.cs` | Подготавливает визуальные слои и рисует карту во всей области элемента |
| `delete.cs` | Пустые файлы без исполняемой логики |

`MainWindow.xaml` и `MainWindow.xaml.cs` находятся в корне WPF-проекта.
Окно создаёт ViewModel, задаёт `DataContext`, вызывает генерацию после `Loaded`
и освобождает ресурсы при закрытии. Ошибки конфигурации показываются отдельным сообщением.

## Данные и потоки

`TerrainViewModel.GenerateAsync` читает `terrain.settings.json` из каталога exe.
Внутренний тип `Settings` описывает необходимые поля JSON.
`Task.Run` выполняет `TerrainGenerator.Generate` вне потока интерфейса.

После `await` выполнение возвращается в WPF-поток, где готовый `TerrainModel`
записывается в `Terrain.Value`. R3 уведомляет WPF-привязку, и она устанавливает
одноимённое dependency property поверхности.

`Dispose` отменяет ожидающие операции и запрещает публикацию результата после закрытия.
Алгоритмы Terrain не опрашивают токен во время своих внутренних циклов.

## Подготовка изображения

При смене модели вызывается `OnTerrainChanged`.
Он один раз восстанавливает отладочную маску исходного каркаса из сохранённых опор
и рёбер, используя существующий растеризатор Брезенхема.
Затем `CreateContourImage` переносит большую маску линий в `BitmapSource`.
Пиксели линий белые, остальные полностью прозрачные.
Изображение замораживается через `Freeze` и используется до следующей смены модели.
Подготовка этих слоёв не изменяет `TerrainModel` и не запускает случайные вычисления.

## Порядок рисования

`OnRender` последовательно рисует:

1. Серый фон во всей области окна
2. Зелёные клетки малой маски, голубые клетки исходного каркаса
3. Тёмно-голубые опорные клетки
4. Тёмные линии малой сетки
5. Чёрные рёбра Прима между центрами опор
6. Белый растровый контур поверх остальных слоёв

Визуальные обозначения взяты из иллюстраций
[статьи Bamboy360](https://bamboy360.com/blog/worms_level_generation/).
Панелей, легенд, кнопок и переключателей в окне нет.
Значения цветов заданы в `TerrainDebugSurface.cs`.

Зелёные клетки показывают имеющуюся малую маску.
Прозрачные внутренности большой маски не заполняются.
Различие между прямоугольными клетками и смещённой белой границей
позволяет видеть переход от малой сетки к общим углам.

## Кадры и изменение размера окна

Размер экранной клетки вычисляется как `ActualWidth / Terrain.Width`
и `ActualHeight / Terrain.Height`. Большая маска растягивается на ту же область.
Пропорции отображения следуют размерам окна, поэтому клетки могут стать прямоугольными.
Для изображения линий используется `NearestNeighbor`, чтобы сохранять пиксельные края.

Изменение модели вызывает перерисовку благодаря `AffectsRender`.
Изменение размеров вызывает `OnRenderSizeChanged` и `InvalidateVisual`.
WPF запрашивает `OnRender`, получает команды рисования, сохраняет их и компонует
готовое изображение в собственном графическом цикле.

Генератор, подготовка растрового каркаса и создание `BitmapSource`
не повторяются на каждом кадре. Собственного `Update`, таймера,
`CompositionTarget.Rendering` или игрового цикла в проекте нет.
