# Генерация земли

Реализованы пункты 3-11 [статьи Bamboy360](https://bamboy360.com/blog/worms_level_generation/):
опорные точки, Prim, Bresenham, нижние массы, рост, общие углы и контуры Павлидиса.
Смещение из пункта 13 применяется при расчёте общих углов.
Внешний край малой сетки остаётся пустым. Большая маска содержит только линии,
сглаживание Чайкина и заполнение внутренностей пока не реализованы.

## Назначение файлов

| Файл | Назначение |
| --- | --- |
| `TerrainGenerator.cs` | Создаёт опоры и MST, растеризует каркас и последовательно вызывает рост и построение контуров |
| `TerrainModel.cs` | Содержит `GridPoint`, `TerrainEdge` и модель малой маски с опорами, рёбрами и результатом контуров |
| `TerrainGrowthSettings.cs` | Описывает параметры роста и проверяет их диапазоны |
| `TerrainGrowth.cs` | Добавляет нижние массы и выполняет синхронные итерации роста |
| `TerrainContourSettings.cs` | Описывает масштаб и силу смещения общих углов |
| `PavlidisContourTracer.cs` | Возвращает упорядоченные замкнутые границы в индексах углов малой сетки |
| `TerrainContourBuilder.cs` | Рассчитывает смещённые общие углы, вызывает Павлидиса и рисует большую маску Брезенхемом |
| `TerrainContourMap.cs` | Содержит `TerrainContour` и `TerrainContourMap`, хранит вершины, признаки отверстий и линии большой маски |
| `delete.cs` | Пустой файл без логики |

## Представление данных

`TerrainModel.Width` и `Height` относятся к малой сетке.
`IsSolid(x, y)` проверяет клетку малой маски и возвращает `false` за её пределами.
`Anchors` и `Edges` описывают исходный каркас, `SolidCellCount` учитывает землю после роста.

`TerrainContourMap.Width` и `Height` относятся к большой маске.
`IsOutline(x, y)` проверяет только пиксель линии, а не наличие земли внутри фигуры.
`GetCellCorners(x, y)` возвращает четыре общих угла клетки в порядке:
левый верхний, правый верхний, правый нижний, левый нижний.
`TerrainContour.Points` содержит замкнутую последовательность без повторения первой точки.
`IsHole` отмечает внутреннюю границу по направлению обхода.

Начало обеих систем координат находится в левом верхнем углу,
X направлен вправо, Y вниз. Экранное масштабирование выполняется только в Presentation.

## Последовательность вычислений

1. `TerrainGenerator` проверяет входные параметры и создаёт до двух фиксированных опор
2. Остальные опоры выбираются по seed из внутренних клеток без повторов
3. Прим строит MST по евклидовым расстояниям, Брезенхем записывает его в малую маску
4. `TerrainGrowth.Apply` добавляет нижние массы и выполняет рост
5. `TerrainContourBuilder.Build` создаёт общие углы со смещениями
6. `PavlidisContourTracer.Trace` выделяет границы в индексах этих углов
7. Границы переводятся в увеличенные координаты и рисуются Брезенхемом
8. Готовые данные возвращаются в `TerrainModel`

Один `Random(seed)` последовательно используется при размещении опор, росте и смещении углов.
Вызов `Generate` без `growth` возвращает каркас без роста,
а без `contours` не создаёт большую маску. Приложение передаёт оба набора настроек из JSON.
Код этой папки не зависит от WPF и может проверяться без окна.

## Конфигурация

Параметры находятся в `terrain.settings.json` в корне WPF-проекта.
При сборке файл копируется к exe. Изменения читаются при следующем запуске.
При запуске из IDE изменяется исходный JSON; при прямом запуске изменяется копия рядом с exe.

| Поле | Назначение |
| --- | --- |
| `Width`, `Height` | Размер малой сетки в клетках, минимум 3 на 3 |
| `Seed` | Целое число для воспроизведения случайных решений |
| `AnchorCount` | Общее число различных опор, включая две фиксированные |
| `Growth.Iterations` | Число полных итераций роста |
| `Growth.UpperRegionHeight` | Доля высоты верхней области, от 0 до 1 |
| `Growth.UpperRegionGrowthChance` | Вероятность роста сверху при двух и более соседях |
| `Growth.SingleNeighborChance` | Вероятность при одном соседе, умножаемая на относительную глубину |
| `Growth.BottomSeedCount` | Число различных стартовых клеток в предпоследней строке |
| `Growth.BottomChunkWidth` | Ширина одного нижнего блока как доля внутренней ширины |
| `Growth.BottomChunkHeight` | Высота нижнего блока как доля внутренней высоты |
| `Contours.UpscaleFactor` | Целый коэффициент увеличения, минимум 1 |
| `Contours.CornerOffset` | Нормализованная сила смещения общих углов от 0 до 1 |

Вероятности и доли должны находиться между 0 и 1. Размеры блока округляются
до клеток; положительная доля даёт хотя бы одну клетку. Нулевая ширина или
высота отключает блок. `BottomSeedCount` не должен превышать `Width - 2`.

## Правила роста

До итераций добавляются случайные нижние клетки и один прямоугольный блок
со случайной горизонтальной позицией. Блок не касается внешнего края.
Затем каждая пустая внутренняя клетка проверяет четыре ортогональных соседа.
При двух и более соседях она заполняется; в верхней области применяется
`UpperRegionGrowthChance`. При одном соседе применяется
`SingleNeighborChance * y / (Height - 1)`. Без соседей роста нет.
Новые клетки записываются после полного обхода, старые не удаляются.

Число итераций, размеры нижнего блока, высотный порог и вероятность одиночного
соседа выбраны как начальные настройки: статья не фиксирует эти значения.
Для просмотра исходного каркаса установить `Iterations` и `BottomSeedCount`
в 0, а `BottomChunkWidth` и `BottomChunkHeight` в 0.

## Общие углы и контуры

Массив общих вершин имеет размер `(Width + 1) x (Height + 1)`.
Каждая клетка получает четыре угла из него, поэтому соседние клетки используют
одинаковые координаты общей стороны. Смещения рассчитываются до обхода контуров.
Максимальный целочисленный сдвиг по каждой оси равен
`floor((UpscaleFactor - 1) * CornerOffset / 4)`, что меньше четверти клетки.
Это выбранное безопасное преобразование нормализованного параметра автора в пиксели.
При `CornerOffset = 0` получается обычная прямоугольная сетка.
При малом масштабе слабое смещение округляется до нуля.

Павлидис реализован по схеме P1, P2, P3 из
[C#-примера](https://gist.github.com/Smurf-IV/45236fc5531535e13b5debbc495c21dc),
с сохранением последовательности точек и проверкой исходной позиции вместе с направлением.
Чтобы перейти от граничных пикселей Павлидиса к углам клеток из статьи,
обход использует виртуальную сетку из четырёх отсчётов на сторону клетки.
Эта техническая адаптация не меняет маску земли и не требует отдельного массива.
Полученные отсчёты переводятся в индексы общих углов.
Касания по одному углу разделяются на отдельные петли.

Для каждой открытой стороны проверяется начальная позиция обхода, поэтому
сохраняются отдельные острова и отверстия. Замкнутые списки вершин хранятся
без дублирования первой точки в конце. Последнее ребро соединяется с первой
вершиной явно и рисуется Брезенхемом вместе с остальными рёбрами.
На экране большая маска белых линий накладывается на цветные клетки малой сетки.
Фон серый, каркас голубой, опоры темнее, земля зелёная, рёбра Прима чёрные.
Это отладочные визуальные слои, внутренняя часть большой маски остаётся пустой.
Текущие настройки `40 x 20` и коэффициент `30` дают `1200 x 600` пикселей.
Малая маска сохраняется отдельно в `TerrainModel`, большая доступна через `ContourMap`.

## Воспроизведение ошибки

Сохранить полный `terrain.settings.json` и версию кода генератора.
Приложение только читает JSON: seed автоматически не меняется и не записывается обратно.
Чтобы получить другую карту, нужно вручную изменить `Seed`.
Одинаковые seed, параметры и версия алгоритма воспроизводят ту же маску
в используемой версии .NET. Автоматическая история предыдущих seeds пока не ведётся.

## Проверки

Из корня репозитория:

Команда доступна при наличии локального каталога `Terrain.Checks`, исключённого из Git-репозитория.

```powershell
dotnet run --project Terrain.Checks/Terrain.Checks.csproj
```

Проверяются каркас, минимальность дерева, растеризация, повторяемость роста,
сохранение земли и границ, отложенная запись, высотные вероятности и параметры.
Контуры проверяются на всех 512 масках 3 x 3, отдельных островах, отверстиях,
тонких перемычках, диагональных касаниях и 100 сгенерированных картах.
Проверяются общие углы, границы смещений, замыкание линий и пустые внутренности.
