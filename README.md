# F2P P2W Worms

Учебный проект локальной пошаговой 2D-игры в духе Worms на C#, XAML и WPF.
Текущая работающая часть проекта - процедурная генерация земли и её отладочное отображение.

## Текущее состояние

Реализованы пункты 3-14 [статьи Bamboy360](https://bamboy360.com/blog/worms_level_generation/):

- Малая бинарная сетка и уникальные опорные точки
- Минимальное остовное дерево Прима
- Пиксельный каркас Брезенхема
- Нижние стартовые клетки, один крупный блок и итерации роста
- Общие углы клеток с небольшими случайными смещениями из пункта 13
- Внешние и внутренние контуры Павлидиса
- Сглаживание замкнутых контуров Чайкином
- Отрисовка сглаженных контуров Брезенхемом в большой бинарной маске
- Классификация областей общим лучом и последовательная заливка BFS
- Параллельная подготовка цветового буфера большой маски по строкам

При текущей конфигурации малая сетка имеет размер `40 x 20`, большая маска `1200 x 600`.
Большая маска содержит землю, воздух и непроходимые пиксели границ.
Обрезка низа, разрушение земли, персонажи, оружие, физика, правила ходов и победа не реализованы.

## Запуск

Требуются Windows, .NET SDK с поддержкой `net9.0-windows` и доступ к NuGet при первом восстановлении.
Единственная явно подключённая библиотека - `R3 1.3.1`.
Графика использует стандартные средства WPF.

Из корня репозитория:

```powershell
dotnet run --project F2P_P2W_Worms/F2P_P2W_Worms.csproj
```

Для работы в Visual Studio открыть `F2P_P2W_Worms.sln`.
Окно развёрнуто и содержит только поверхность карты.

## Настройки и seed

Конфигурация находится в [terrain.settings.json](F2P_P2W_Worms/terrain.settings.json).
Размер сетки, число точек, seed, параметры роста, масштаб, смещение углов, сглаживание и отладочные слои
читаются при запуске. При сборке JSON копируется рядом с exe.

Приложение только читает конфигурацию. Seed не изменяется автоматически.
Одинаковые seed, параметры, версия алгоритма и используемая версия .NET воспроизводят карту.
Для повторения ошибки сохраняются полный JSON и версия кода.

При запуске из IDE изменяется исходный JSON с последующей сборкой и перезапуском.
При прямом запуске exe изменяется JSON рядом с ним с последующим перезапуском.
Допустимые значения описаны в разделе [Конфигурация](#конфигурация).

## Terrain

Папка `F2P_P2W_Worms/Terrain` содержит данные и алгоритмы без зависимости от WPF.

### Назначение файлов

| Файл | Назначение |
| --- | --- |
| `TerrainGenerator.cs` | Создаёт каркас, выполняет рост, построение контуров и последовательную заливку |
| `TerrainModel.cs` | Содержит `GridPoint`, `TerrainEdge`, малую маску, опоры, рёбра, контуры и большую маску земли |
| `TerrainGrowthSettings.cs` | Описывает параметры роста и проверяет их диапазоны |
| `TerrainGrowth.cs` | Добавляет нижние массы и выполняет синхронные итерации роста |
| `TerrainContourSettings.cs` | Описывает масштаб, смещение углов, число итераций и долю среза Чайкина |
| `PavlidisContourTracer.cs` | Возвращает упорядоченные замкнутые границы в индексах углов малой сетки |
| `TerrainContourBuilder.cs` | Рассчитывает общие углы, вызывает Павлидиса и Чайкина, округляет вершины и рисует маску Брезенхемом |
| `ChaikinSmoother.cs` | Содержит дробную точку `ContourPoint` и сглаживает замкнутые контуры без промежуточного округления |
| `TerrainContourMap.cs` | Содержит `TerrainContour` и `TerrainContourMap`, хранит вершины, признаки отверстий и общий барьер |
| `TerrainFill.cs` | Содержит `TerrainFill` и `TerrainFillResult`, выполняет геометрическую классификацию и BFS, хранит большую маску и время заливки |
| `delete.cs` | Пустой файл без логики |

### Представление данных

`TerrainModel.Width` и `Height` относятся к малой сетке.
`IsSolid(x, y)` проверяет клетку малой маски и возвращает `false` за её пределами.
`Anchors` и `Edges` описывают исходный каркас, `SolidCellCount` учитывает землю после роста.

`TerrainContourMap.Width` и `Height` относятся к большой маске.
`IsOutline(x, y)` проверяет только пиксель линии, а не наличие земли внутри фигуры.
`GetCellCorners(x, y)` возвращает четыре общих угла клетки в порядке:
левый верхний, правый верхний, правый нижний, левый нижний.
`TerrainContour.Points` содержит округлённые вершины сглаженного контура без соседних повторений и повторения первой точки в конце.
`ContourPoint` хранит дробные координаты во время сглаживания.
`IsHole` отмечает внутреннюю границу по направлению обхода и сохраняется как метаданные.
Заливка его не использует.

`TerrainModel.FilledMap` содержит большую маску `TerrainFillResult`.
Её `IsSolid(x, y)` проверяет материал пикселя в большом разрешении.
`RegionCount` показывает число областей вне барьера, классифицированных лучом.
`SolidPixelCount` включает землю внутри областей и все пиксели границ.
`Duration` содержит время заливки вместе с выделением её рабочих массивов.

Начало обеих систем координат находится в левом верхнем углу,
X направлен вправо, Y вниз. Экранное масштабирование выполняется только в Presentation.

### Последовательность вычислений

1. `TerrainGenerator` проверяет входные параметры и создаёт до двух фиксированных опор
2. Остальные опоры выбираются по seed из внутренних клеток без повторов
3. Прим строит MST по евклидовым расстояниям, Брезенхем записывает его в малую маску
4. `TerrainGrowth.Apply` добавляет нижние массы и выполняет рост
5. `TerrainContourBuilder.Build` создаёт общие углы со смещениями
6. `PavlidisContourTracer.Trace` выделяет границы в индексах этих углов
7. Границы переводятся в увеличенные координаты и сглаживаются `ChaikinSmoother`
8. Готовые кривые округляются до пикселей и рисуются Брезенхемом
9. `TerrainFill.Fill` классифицирует области и заполняет большую маску
10. Готовые данные возвращаются в `TerrainModel`

Один `Random(seed)` последовательно используется при размещении опор, росте и смещении углов.
Вызов `Generate` без `growth` возвращает каркас без роста,
а без `contours` не создаёт большую маску. Приложение передаёт оба набора настроек из JSON.
Код этой папки не зависит от WPF и может проверяться без окна.

### Конфигурация

Параметры находятся в `terrain.settings.json` в корне WPF-проекта.
При сборке файл копируется к exe. Изменения читаются при следующем запуске.
При запуске из IDE изменяется исходный JSON; при прямом запуске изменяется копия рядом с exe.

| Поле | Назначение |
| --- | --- |
| `Width`, `Height` | Размер малой сетки в клетках, минимум 3 на 3 |
| `Seed` | Целое число для воспроизведения случайных решений |
| `ShowDebugLayers` | При `true` видны каркас и сетка, при `false` только большая маска и контур |
| `AnchorCount` | Общее число различных опор, включая две фиксированные |
| `Growth.Iterations` | Число полных итераций роста |
| `Growth.UpperRegionHeight` | Доля высоты верхней области, от 0 до 1 |
| `Growth.UpperRegionGrowthChance` | Вероятность роста сверху при двух и более соседях |
| `Growth.SingleNeighborChance` | Вероятность при одном соседе, умножаемая на относительную глубину |
| `Growth.BottomSeedCount` | Число различных стартовых клеток в предпоследней строке |
| `Growth.BottomChunkWidth` | Ширина одного нижнего блока как доля внутренней ширины |
| `Growth.BottomChunkHeight` | Высота нижнего блока как доля внутренней высоты |
| `Contours.UpscaleFactor` | Целый коэффициент увеличения, минимум 1 |
| `Contours.CornerOffset` | Нормализованная сила смещения общих углов от 0 до 1 |
| `Contours.SmoothingIterations` | Число итераций Чайкина от 0 до 8, по умолчанию 3 |
| `Contours.CutRatio` | Доля среза ребра, строго между 0 и 0.5, по умолчанию 0.25 |

Вероятности и доли должны находиться между 0 и 1. Размеры блока округляются
до клеток; положительная доля даёт хотя бы одну клетку. Нулевая ширина или
высота отключает блок. `BottomSeedCount` не должен превышать `Width - 2`.
Текущие нижние добавки: 3 стартовые клетки, ширина блока `0.3`, высота `0.12`
от внутреннего размера сетки. Вероятность роста сверху при двух и более соседях равна `0.5`.

### Правила роста

До итераций добавляются случайные нижние клетки и один прямоугольный блок
со случайной горизонтальной позицией. Блок не касается внешнего края.
Затем каждая пустая внутренняя клетка проверяет четыре ортогональных соседа.
При двух и более соседях она заполняется; в верхней области применяется
`UpperRegionGrowthChance`. При одном соседе применяется
`SingleNeighborChance * y / (Height - 1)`. Без соседей роста нет.
Новые клетки записываются после полного обхода, старые не удаляются.

Число итераций, размеры нижнего блока, высотный порог и вероятность одиночного
соседа выбраны как начальные настройки: статья не фиксирует эти значения.
Для просмотра исходного каркаса установить `Iterations` и `BottomSeedCount`
в 0, а `BottomChunkWidth` и `BottomChunkHeight` в 0.

### Общие углы и контуры

Массив общих вершин имеет размер `(Width + 1) x (Height + 1)`.
Каждая клетка получает четыре угла из него, поэтому соседние клетки используют
одинаковые координаты общей стороны. Смещения рассчитываются до обхода контуров.
Максимальный целочисленный сдвиг по каждой оси равен
`floor((UpscaleFactor - 1) * CornerOffset / 4)`, что меньше четверти клетки.
Это выбранное безопасное преобразование нормализованного параметра автора в пиксели.
При `CornerOffset = 0` получается обычная прямоугольная сетка.
При малом масштабе слабое смещение округляется до нуля.

Павлидис реализован по схеме P1, P2, P3 из
[C#-примера](https://gist.github.com/Smurf-IV/45236fc5531535e13b5debbc495c21dc),
с сохранением последовательности точек и проверкой исходной позиции вместе с направлением.
Чтобы перейти от граничных пикселей Павлидиса к углам клеток из статьи,
обход использует виртуальную сетку из четырёх отсчётов на сторону клетки.
Эта техническая адаптация не меняет маску земли и не требует отдельного массива.
Полученные отсчёты переводятся в индексы общих углов.
Касания по одному углу разделяются на отдельные петли.

Для каждой открытой стороны проверяется начальная позиция обхода, поэтому
сохраняются отдельные острова и отверстия. Замкнутые списки вершин хранятся
без дублирования первой точки в конце. Последнее ребро соединяется с первой
вершиной явно и рисуется Брезенхемом вместе с остальными рёбрами.
На экране большая маска белых линий накладывается на цветные клетки малой сетки.
Фон серый, каркас голубой, опоры темнее, земля зелёная, рёбра Прима чёрные.
Зелёная область берётся из заполненной большой маски, отладочные цвета ограничены этой областью.
Текущие настройки `40 x 20` и коэффициент `30` дают `1200 x 600` пикселей.
Малая маска сохраняется отдельно в `TerrainModel`, большая доступна через `ContourMap`.

### Сглаживание Чайкина

После Павлидиса вершины каждого контура переводятся в увеличенные координаты.
Для каждой пары соседних точек `A` и `B` создаются две точки:

```text
Q = (1 - r) * A + r * B
R = r * A + (1 - r) * B
```

`r` задаётся в `Contours.CutRatio`. Замыкающее ребро от последней точки к первой
обрабатывается тем же способом. На каждой итерации число дробных вершин удваивается.
При трёх итерациях оно увеличивается в восемь раз.

Вычисления между итерациями сохраняют дробные координаты.
Только готовая кривая округляется до пикселей, с половинами от нуля.
Соседние повторные пиксельные вершины удаляются, затем все рёбра рисуются Брезенхемом.
Признаки отверстий и отдельные контуры сохраняются, малая маска и общие углы не меняются.
При небольшом масштабе число различных пиксельных вершин может быть меньше числа дробных точек.

`SmoothingIterations = 0` отключает сглаживание и показывает исходную границу.
Ограничение в восемь итераций сдерживает экспоненциальный рост числа вершин.
Доля среза проверяется даже при нуле итераций.
Реализация следует описанию замкнутых кривых в
[материале Sighack](https://sighack.com/post/chaikin-curves), указанном автором основной статьи.

Общая маска линий сохраняется отдельно как барьер для последующего BFS.
Сглаживание не меняет малую маску земли.

### Заливка большой маски

`TerrainFill.Fill` использует одну общую растровую маску всех сглаженных контуров.
Пиксели барьера сразу назначаются землёй. Остальные пиксели последовательно
перебираются по строкам. Для первого непосещённого пикселя выпускается
математический горизонтальный луч вправо через отрезки всех контуров вместе.
Нечётное число пересечений означает землю, чётное означает воздух.

Координаты центров пикселей совпадают с целыми координатами Брезенхема.
Условие `(a.Y > y) != (b.Y > y)` задаёт полуоткрытый диапазон пересечения:
горизонтальные рёбра не учитываются, вершины не дают двойного пересечения.

Материал найденной области назначается последовательным BFS по четырём соседям.
Через барьер переходить нельзя. Пиксель помечается посещённым при добавлении
в очередь. Геометрия проверяется один раз на область, а не для каждого её пикселя.
Рабочие структуры общие: итоговый массив, массив посещения и очередь.
Отдельных масок для каждого контура, вычитания полостей и зависимости от `IsHole` нет.
Чётность всех границ сохраняет полости и островки внутри них.

## Presentation

Слой получает готовую большую маску Terrain и подготавливает её отображение.
Данные вычисляются обычными массивами в фоне, WPF-объекты создаются в UI-потоке.

### Назначение файлов

| Файл | Назначение |
| --- | --- |
| `ViewModels/TerrainViewModel.cs` | Читает JSON, запускает генерацию, заливку и буфер в фоне, публикует `Frame.Value` через R3 |
| `TerrainPixelBuffer.cs` | Содержит `TerrainFrame` и подготовку BGRA по независимым строкам через `Parallel.For` |
| `Views/TerrainView.xaml` | Содержит `TerrainDebugSurface` с привязкой `Frame.Value` |
| `Views/TerrainView.xaml.cs` | Инициализирует XAML-представление |
| `Views/TerrainDebugSurface.cs` | Создаёт WPF-изображение в UI-потоке и рисует его с отладочными линиями |
| `delete.cs` | Пустые файлы без исполняемой логики |

### Данные и потоки

`MainWindow.Loaded` вызывает `TerrainViewModel.GenerateAsync` один раз.
Внутренний `Settings` описывает JSON из каталога exe.
Внутри `Task.Run` выполняются `TerrainGenerator.Generate`, последовательная заливка
и подготовка цветового буфера через `TerrainPixelBuffer.Create`.
Каждая итерация `Parallel.For` записывает только свою строку массива BGRA.
Маски читаются без изменений. В рабочих потоках нет объектов WPF.

`TerrainFrame` содержит модель карты, готовый массив пикселей, флаг отладки
и длительность подготовки буфера. После `await` выполнение возвращается
в UI-поток и устанавливает `Frame.Value`. R3 уведомляет WPF-привязку.
`OnFrameChanged` проверяет доступ через Dispatcher и создаёт `BitmapSource`
из готового массива. Замороженное изображение используется до следующего кадра данных.

`Dispose` отменяет ожидающие операции и запрещает публикацию результата после закрытия.
Алгоритмы Terrain не опрашивают токен во время внутренних циклов.

### Цветовой буфер и отладочные слои

`TerrainPixelBuffer.Create` имеет последовательный и параллельный варианты
с одинаковой логикой строки. Воздух прозрачен, земля зелёная, общий барьер белый.
При включённой отладке каркас голубой, опорные клетки темнее.
Эти цвета записываются только внутри заполненной большой маски.
Маленькие вспомогательные массивы каркаса и опор служат только для цветов.

`OnRender` рисует серый фон, большую маску и, при `ShowDebugLayers = true`,
тёмную сетку и чёрные рёбра Прима. Параметр меняется в JSON до запуска.
При `false` можно увидеть большую маску без малой сетки и каркаса.
В окне нет новых панелей, подписей и кнопок.

## Принцип работы и взаимодействие

```text
App.xaml
  -> MainWindow
  -> TerrainViewModel.GenerateAsync
  -> чтение terrain.settings.json
  -> Task.Run: TerrainGenerator.Generate
       -> точки -> Prim -> Bresenham
       -> TerrainGrowth
       -> TerrainContourBuilder
            -> общие углы со смещениями
            -> PavlidisContourTracer
            -> ChaikinSmoother
            -> округление вершин
            -> Bresenham в большую маску
       -> TerrainFill: луч и последовательный BFS
       -> TerrainModel
  -> TerrainPixelBuffer: Parallel.For по строкам
  -> TerrainFrame
  -> TerrainViewModel.Frame.Value
  -> WPF Binding в TerrainView
  -> TerrainDebugSurface
```

`TerrainModel` хранит малую маску земли, опоры и рёбра.
`TerrainContourMap` хранит общие углы, упорядоченные контуры и общий барьер.
`TerrainFillResult` хранит заполненную большую маску.
Генерация выполняется в фоне. После `await` ViewModel передаёт готовую модель
в интерфейс через `BindableReactiveProperty` из R3.
Классы Terrain не зависят от WPF, ViewModel связывает вычисления с представлением,
а поверхность отвечает только за показ данных.

## Как получается изображение и каждый кадр

Сейчас приложение показывает статическую сгенерированную карту.
Собственного игрового цикла, обновления физики и обработчика каждого кадра нет.

1. При запуске `MainWindow.Loaded` вызывает генерацию один раз
2. В фоне готовятся геометрия, заливка и массив цветных пикселей
3. В UI-потоке WPF-привязка меняет `TerrainDebugSurface.Frame`, `OnFrameChanged` создаёт изображение
4. Изменение свойства помечает элемент для отрисовки, WPF вызывает `OnRender`
5. `OnRender` рисует готовую большую маску и выбранные отладочные слои
6. WPF сохраняет команды рисования и использует их при композиции отображаемых кадров

Частота обновления монитора не запускает генератор заново.
`OnRender` также не обязан вызываться на каждом обновлении монитора.
При изменении размера окна поверхность запрашивает перерисовку и пересчитывает
экранные размеры клеток. Данные карты и seed при этом не меняются.
Большая маска растягивается на ту же область, что и малая сетка. Размеры экранной клетки
равны `ActualWidth / Terrain.Width` и `ActualHeight / Terrain.Height`. Клетки могут стать
прямоугольными при несовпадении пропорций окна и карты. Для контура используется
`NearestNeighbor`, сохраняющий пиксельные края.
Подробнее порядок слоёв и работа потоков описаны в разделе [Presentation](#presentation).

## Визуальные обозначения

Оформление следует обозначениям иллюстраций основной статьи:
серый фон, тёмная сетка, зелёные клетки земли, голубой каркас,
тёмно-голубые опорные клетки, чёрные рёбра Прима и белый контур.

Зелёная область показывает заполненную большую маску.
Белые линии показывают сглаженный растровый барьер.
Каркас и малая сетка накладываются как отладочные ориентиры.
Цвета не влияют на данные генератора.

## Проверки

Каталог `Terrain.Checks` хранится локально и исключён из Git-репозитория.
При клонировании проекта с GitHub он не загружается.
При наличии локального каталога проверки запускаются командой:

```powershell
dotnet run --project Terrain.Checks/Terrain.Checks.csproj
```

Программа содержит 26 групп проверок и возвращает ненулевой код при ошибке.
Проверяются минимальность дерева, растеризация, рост, контуры,
общие углы, границы массивов и воспроизводимость.

### Проверяемые свойства

- Повторяемость точек, рёбер и маски на 100 seeds
- Уникальность опор, пустые границы и связность каркаса
- Минимальность Прима через независимый эталон Краскала
- Пустой граф, одна вершина, равные веса и повторные точки
- Брезенхем на всех 6561 парах концов отрезка в сетке 9 x 9
- Известные отрезки, неверные параметры и малые размеры сеток
- Отложенная запись роста и четыре ортогональных соседа
- Высотные вероятности и стартовые нижние массы
- Повторяемость роста, сохранение каркаса и границ
- Ориентированные рёбра Павлидиса на всех 512 масках 3 x 3
- Острова, отверстия, тонкие перемычки и касания по углу
- Общие координаты углов, безопасные смещения и их повторяемость
- Размер большой маски, замыкание контуров и пустые внутренности
- Полный конвейер контуров на 100 seeds и проверка параметров
- Чайкин на известных координатах, удвоение числа вершин и замыкающее ребро
- Дробные промежуточные вычисления, направление обхода и сохранение входных данных
- Повторяемость сглаживания, замкнутая растеризация и отсутствие заливки
- Диапазоны параметров сглаживания
- Земля с полостью, остров внутри неё и несколько отдельных кусков
- Горизонтальные рёбра, вершины и независимость от `IsHole`
- Диагонали, узкие проходы и попиксельное сравнение с независимым вертикальным лучом
- Повторяемость заполненных масок
- Полное совпадение последовательного и параллельного BGRA, прозрачность воздуха и цвета материалов

Для высотных вероятностей используется `ConstantRandom` с заданным значением.
Проверки не зависят от ручного наблюдения случайной частоты событий.
Отображение, привязки WPF и компоновка окна проверяются при запуске приложения.

При успехе выводится `26/26 groups passed.` и возвращается код 0.
При ошибке выводится `FAIL` с описанием и возвращается код 1.

## Измерения

Локальный замер в Debug, .NET 9, доступно 24 логических процессора.
Для каждого размера выполняются 2 прогрева и 7 измерений, в таблице медианы.
Использован seed `20261125`, отладочные цвета включены.
Первый размер соответствует текущему JSON, второй использует малую сетку `64 x 36`.

| Размер маски | Заливка BFS с лучом, мс | Буфер последовательно, мс | Буфер Parallel.For, мс |
| --- | ---: | ---: | ---: |
| 1200 x 600 | 95.570 | 41.005 | 8.212 |
| 1920 x 1080 | 273.581 | 102.085 | 16.432 |

Заливка измеряется отдельно от генерации контуров и включает выделение её массивов.
Подготовка буфера включает массив BGRA, отладочные маски и запись цветов.
Создание `BitmapSource` не входит в эти значения и выполняется только в UI-потоке.
Его длительность, время заливки и время буфера выводятся через `Trace.WriteLine`
при получении кадра. Содержимое рабочего окна для измерений не изменяется.

На этой машине параллельная подготовка быстрее в обоих замерах.
Это локальный результат, а не гарантия ускорения для любого размера и компьютера.
Повторный запуск локальных проверок заново измеряет оба варианта.
