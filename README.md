# F2P P2W Worms

Учебный проект локальной пошаговой 2D-игры в духе Worms на C#, XAML и WPF.
Текущая работающая часть проекта - процедурная генерация земли и её отладочное отображение.

## Текущее состояние

Реализованы пункты 3-11 [статьи Bamboy360](https://bamboy360.com/blog/worms_level_generation/):

- Малая бинарная сетка и уникальные опорные точки
- Минимальное остовное дерево Прима
- Пиксельный каркас Брезенхема
- Нижние стартовые клетки, один крупный блок и итерации роста
- Общие углы клеток с небольшими случайными смещениями из пункта 13
- Внешние и внутренние контуры Павлидиса
- Отрисовка замкнутых контуров Брезенхемом в большой бинарной маске

При текущей конфигурации малая сетка имеет размер `40 x 20`, большая маска `1200 x 600`.
Большая маска содержит только линии. Сглаживание Чайкина, Flood Fill, обрезка низа,
разрушение земли, персонажи, оружие, физика, правила ходов и победа не реализованы.

## Запуск

Требуются Windows, .NET SDK с поддержкой `net9.0-windows` и доступ к NuGet при первом восстановлении.
Единственная явно подключённая библиотека - `R3 1.3.1`.
Графика использует стандартные средства WPF.

Из корня репозитория:

```powershell
dotnet run --project F2P_P2W_Worms/F2P_P2W_Worms.csproj
```

Для работы в Visual Studio открыть `F2P_P2W_Worms.sln`.
Окно развёрнуто и содержит только поверхность карты.

## Настройки и seed

Конфигурация находится в [terrain.settings.json](F2P_P2W_Worms/terrain.settings.json).
Размер сетки, число точек, seed, параметры роста, масштаб и смещение углов
читаются при запуске. При сборке JSON копируется рядом с exe.

Приложение только читает конфигурацию. Seed не изменяется автоматически.
Одинаковые seed, параметры, версия алгоритма и используемая версия .NET воспроизводят карту.
Для повторения ошибки сохраняются полный JSON и версия кода.

При запуске из IDE изменяется исходный JSON с последующей сборкой и перезапуском.
При прямом запуске exe изменяется JSON рядом с ним с последующим перезапуском.
Допустимые значения описаны в [Terrain/README.md](F2P_P2W_Worms/Terrain/README.md).

## Принцип работы и взаимодействие

```text
App.xaml
  -> MainWindow
  -> TerrainViewModel.GenerateAsync
  -> чтение terrain.settings.json
  -> Task.Run: TerrainGenerator.Generate
       -> точки -> Prim -> Bresenham
       -> TerrainGrowth
       -> TerrainContourBuilder
            -> общие углы со смещениями
            -> PavlidisContourTracer
            -> Bresenham в большую маску
       -> TerrainModel
  -> TerrainViewModel.Terrain.Value
  -> WPF Binding в TerrainView
  -> TerrainDebugSurface
```

`TerrainModel` хранит малую маску земли, опоры и рёбра.
`TerrainContourMap` хранит общие углы, упорядоченные контуры и большую маску линий.
Генерация выполняется в фоне. После `await` ViewModel передаёт готовую модель
в интерфейс через `BindableReactiveProperty` из R3.
Классы Terrain не зависят от WPF, ViewModel связывает вычисления с представлением,
а поверхность отвечает только за показ данных.

## Как получается изображение и каждый кадр

Сейчас приложение показывает статическую сгенерированную карту.
Собственного игрового цикла, обновления физики и обработчика каждого кадра нет.

1. При запуске `MainWindow.Loaded` вызывает генерацию один раз
2. После получения модели WPF-привязка меняет свойство `TerrainDebugSurface.Terrain`
3. `OnTerrainChanged` подготавливает маленький растровый каркас и прозрачное изображение большого контура
4. Изменение свойства помечает элемент для отрисовки, WPF вызывает `OnRender`
5. `OnRender` рисует фон, клетки, опоры, сетку, рёбра и изображение контура
6. WPF сохраняет команды рисования и использует их при композиции отображаемых кадров

Частота обновления монитора не запускает генератор заново.
`OnRender` также не обязан вызываться на каждом обновлении монитора.
При изменении размера окна поверхность запрашивает перерисовку и пересчитывает
экранные размеры клеток. Данные карты и seed при этом не меняются.
Подробнее порядок слоёв и работа потоков описаны в [Presentation](F2P_P2W_Worms/Presentation/README.md).

## Визуальные обозначения

Оформление следует обозначениям иллюстраций основной статьи:
серый фон, тёмная сетка, зелёные клетки земли, голубой каркас,
тёмно-голубые опорные клетки, чёрные рёбра Прима и белый контур.

Зелёная область показывает малую маску после роста, а не результат Flood Fill.
Белые линии показывают большую маску контуров со смещёнными углами.
Поэтому белая граница может проходить немного в стороне от прямоугольных клеток.
Цвета не влияют на данные генератора.

## Проверки

Каталог `Terrain.Checks` хранится локально и исключён из Git-репозитория.
При клонировании проекта с GitHub он не загружается.
При наличии локального каталога проверки запускаются командой:

```powershell
dotnet run --project Terrain.Checks/Terrain.Checks.csproj
```

Программа содержит 16 групп проверок и возвращает ненулевой код при ошибке.
Проверяются минимальность дерева, растеризация, рост, контуры,
общие углы, границы массивов и воспроизводимость.
